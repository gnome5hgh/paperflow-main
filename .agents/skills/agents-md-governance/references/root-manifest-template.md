# 根 manifest 模板

抄这份骨架，把 `<尖括号>` 换成你项目的事实，删掉 `<!-- -->` 注释。**节名与顺序不要改**——固定骨架的价值就在可机械校验、跨项目可检索。填不出来的节（比如纯库项目没有「环境与依赖」）保留标题写「无」，不要删节也不要编。

```markdown
# AGENTS.md

本文件为 AI 编码代理（ZCode / Claude Code / Codex 等）提供 `<项目名>` 的进入方式、阅读路径与必须遵守的规则。

**本文件只写规则，不写现状快照**：字段表、文件清单、枚举取值、当前数量都以源码为准，抄一份到这里必然过期。判据是「删掉它，agent 会不会做错事」——不会、但得去源码翻的，就删掉。唯一保留的非规则是**导航**。

## Scope

- 本文件是 `<项目/工作区>` 的总 manifest，负责建立边界、阅读路径、治理规则与公共约束。
- 作用范围覆盖整个仓库；进入更深层目录后，服从该目录更近的 `AGENTS.md`。
- **子 manifest 不会自动注入**（客户端只注入从当前目录向上找到的第一份，不逐层合并）：**改某个模块之前，按 Routing 主动读它那份**。
- 事实优先级：源码与测试 > manifest > 设计文档。文档与代码冲突时以代码为准。

## 模块定位

- 名称：`<项目名>`
- 路径：`.`
- 角色：`repo-root-workspace-manifest`
- 当前定位：<一句话说清它是什么、给谁用>
- 绑定环境：<语言版本 / 运行时 / 包管理器>

## 目录结构

```text
<项目名>/
├─ <一级目录>/          # 一行用途
├─ <一级目录>/          # 一行用途
└─ AGENTS.md
```

### 当前目录分层含义

- <哪个目录是代码事实源、哪个是产物、哪个是文档>
- <哪些目录**不入库**、为什么；不入库意味着它们的漂移不会被 diff 顶出来>
- 运行期目录与生成物不作事实源，除非明确要求排查运行时现象。

## 技术结构

- 语言与运行时：<版本；依赖声明在哪个文件>
- 依赖服务：<数据库/队列/对象存储等，怎么起（compose / 脚本）>
- 外部端点：<第三方 API 的类别与配置位置>
- 可调参数的唯一声明点：`<文件路径>`；配置文件是纯覆盖。

## 环境与依赖

- 必须提供的密钥：<有哪几类、配在哪、缺失时的行为（fail-fast 还是降级）>
- 必须显式配置的路径：<如数据目录；**没有默认值**，问用户要，不要猜、不要填占位值>
- 软依赖：<不可达只警告降级的那些；以及哪些测试/评测需要真服务>

## 仓库职责

- <承载什么功能>
- <维护什么契约>
- <维护哪些资产（文档体系、插件、模板）>

## 核心协作逻辑

- <系统怎么运转，3–6 条，每条一句话>
- <谁调度谁、边界在哪>
- <哪些一致性靠代码保证、哪些靠契约保证>

## 硬红线

不分模块、任何地方都必须成立的不变式。违反它们通常不报错，只会让功能静默失效或让设计倒退。

- <错误处理的总约定：错误如何向上传播或降级>
- <数据真相源是谁、什么投影是可重建的>
- <安全/权限的边界：哪些是强制、哪些只是提示>
- <并发与状态的约定：状态放哪、谁能写>
- <不许复活的东西：已退役的实现与「旧文档不作论据」>

## 关键入口

- <进程入口 / 装配根>
- <参数声明点 / 配置模板>
- <插件或扩展的契约文件>
- <设计文档索引>

## 渐进式阅读路径

- 仓库边界与公共规则：先读本文件。
- <改某个子系统>：`<子 manifest>` → 源码与测试。
- 追设计背景：`<设计文档目录>`。
- 排查异常：`<排障 skill 或清单>`。

## 调查规则

1. 先读本文件建立边界，再按 Routing 读目标模块那份子 manifest，最后才读源码。
2. 设计背景查 `<设计文档目录>`；历史决策查 `<修正记录>`。
3. manifest 不够用时深入源码、包清单与调用链核实。**代码事实优先于任何文档概括**。
4. <项目特有的调查纪律，如「测试目录不入库，所以改完要主动核对」>
5. 运行期目录与 gitignored 产物不作事实源，除非明确要求排查运行时现象。

## 常用命令

```bash
<安装依赖>
<全量测试>
<单个测试>
<起依赖服务>
<启动应用>
```

- <每条命令的陷阱：哪个命令不能经某个包装器、哪个必须用虚拟环境、哪个会 EOF>
- <非交互命令的固定前缀，例如 `conda run -n <env>` 或 `<pkg> exec`>

## 统一编码规范

- <注释写给谁、用什么语言、不许出现什么（内部代号、日期、文档章节引用）>
- <docstring 风格与必备段落；哪种情况可以省略>
- <与语言默认不同的风格约定>
- <复用优先：新增前先检索既有实现，禁止平行造轮子>
- <命名与目录落位的一致性要求>

## 文档维护规则

- **本文件与各级子 manifest 只写规则**，不写容易失效的静态计数、一次性状态或临时结论。
- **改代码后先自问要不要同步设计文档**：接口签名、行为语义、结构或已记录决策变化都算。需要同步时**先让测试通过再改文档**。
- <设计文档体系：一份一主题还是按模块；正文恒为最新还是只追加；历史记在哪一个文件里>
- <实施期文档（spec/plan）的回修规则>
- <不入库的文档目录 + 「漂移不会被 git 顶出来」的提醒>

## Routing

- 当前目录是 `<项目名>` 的根工作区 manifest。
- 主入口：[`<子目录>/AGENTS.md`](<子目录>/AGENTS.md)
- 设计文档索引：[`<设计文档目录>/`](<设计文档目录>/)
- 排障 skill：[`.agents/skills/<名>/SKILL.md`](.agents/skills/<名>/SKILL.md)

## References

- [`README.md`](README.md)
- [`<配置文件模板>`](<配置文件模板>)
- [`<依赖清单>`](<依赖清单>)
- [`<子目录>/AGENTS.md`](<子目录>/AGENTS.md)
```

## 每节最容易写错的点

| 节 | 容易犯的错 | 正确做法 |
|---|---|---|
| Scope | 罗列所有子 manifest（会漂） | 只写「范围 + 事实优先级 + 子 manifest 要靠 Routing 主动读」，清单交给 Routing |
| 目录结构 | 逐文件写职责 | 写到「一层目录 + 一行用途」；细节归子 manifest |
| 技术结构 | 抄一长串依赖版本 | 只写「基线从哪个文件读」+ 少数几个真正影响写代码的版本 |
| 环境与依赖 | 把默认值抄一遍 | 只写「必须由人提供的东西」+ 缺失时的行为 |
| 硬红线 | 变成设计叙事 | 每条必须是**可判定**的不变式：违反了就是 bug |
| 常用命令 | 只贴命令不写陷阱 | 陷阱比命令值钱（哪个包装器不能用、哪个会 EOF） |
| 统一编码规范 | 抄语言通用惯例 | 只写「与默认不同」的和「本项目特有」的 |
| 文档维护规则 | 只写「要更新文档」 | 写清历史记在哪、正文是否恒为最新、spec/plan 怎么回修 |
| Routing / References | 链接不校验 | 每次改动后跑一遍链接校验（见 audit-checklist） |
