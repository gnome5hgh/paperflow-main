# retrieval-quality — 检索不到 / 不准 / 索引异常

「能跑但结果不对」先分诊：索引缺失 vs 链路降级 vs 评测口径，再对症。条目按发现顺序追加。

### 明明有这篇文献却检索不到（索引缺失分诊）
- **根因**（按序排查三种）：①索引时 GROBID 超时回退 PyMuPDF，解析质量差导致切块无有效内容；②嵌入 key 未配，稠密路静默降级；③查询改写噪声把查询带偏。
- **修法**：①查 GROBID 健康、对该 PDF 单独重建索引；②查 `rag.embedding.api_key`；③用原查询（关改写）复测，看命中是否恢复。
- **验证**：定位到三种之一并按对应修法后，该文献在 top-k 内出现。

### 检索质量整体下降（参数与评测口径核对）
- **根因**：可调参数被改动，或评测被改写噪声干扰（改写器 LLM 噪声 mrr ±0.034，曾压过参数效应）。
- **修法**：核对 `rrf_k=30`、`rerank_candidates=24`（config.py 唯一声明点）；归因评测用冻结改写集（噪声 ±0.0003），脚本在 `scripts/rag/`。
- **验证**：冻结改写集评测 mrr 回到基线 ±0.01 内。

### 引用出处对不上 / 溯源可疑（citation provenance）
- **根因**：引用溯源链路（ADR 0008）的 span 对齐问题，或上游检索块本身错——先确认块对、再查溯源映射。
- **修法**：定位可疑引用的来源块 id，核对该块原文与答案中引用句；块对则查溯源映射代码，块错则回到检索条目分诊。
- **验证**：可疑引用逐一核对，能指出映射错误的具体环节。
